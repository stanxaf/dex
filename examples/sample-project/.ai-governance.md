# Example project configuration

This is a fictional configuration for demonstration, not a deployable project or evidence of compliance.

- Selected profile: regulated; read the installed baseline, web-saas, and regulated profiles and the foundation workflow.
- Domain rules: `domain-extension.md`; payroll lead owns rule interpretation and approvals.
- Architecture and data access: a hypothetical server-side pay-run API; document real contracts and tenant boundaries before implementation.
- Design sources: hypothetical existing component registry; locate actual tokens, components and baselines before UI work.
- Checks: none configured in this example. A real project must specify and require actual lint, type, unit, integration, authorization, accessibility, visual, security and migration checks as appropriate. Missing required checks block merging.
- Independent validation and release: assigned project domain owner and independent human reviewer; production deployment requires separate approval.
- Decisions and exceptions: create project-owned records using foundation templates.
