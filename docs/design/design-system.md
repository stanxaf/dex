# UI and design-system governance

Read the project design sources in `.ai-governance.md`. Prefer approved components, tokens, typography, spacing and established layouts. Do not introduce competing components, colors, values or conventions when approved alternatives fit. Assess the affected semantics, labels, focus, keyboard behavior, accessible names, error associations, contrast, responsive reflow and component states. Validate form input server-side and explain errors accessibly. Select rendered, interaction and visual-regression checks using the [workflow](../agent-governance/workflow.md#selecting-verification); review intended baseline changes and run required checks at their stated checkpoints.

When a gap exists, document use cases, alternatives, token/component impact, accessibility and responsive behavior, and propose an extension to the design-system owner before introducing a shared pattern. Local exceptions need a documented owner and exit plan. If no system exists, identify existing product conventions, use semantic platform primitives, document a small consistent set of choices, and request approval for consequential visual decisions; do not invent a full system by default. The configuration template records source-of-truth and baseline locations.
