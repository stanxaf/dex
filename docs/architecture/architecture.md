# Architecture and decisions

Use the existing project architecture and record module boundaries, dependency directions, data flow, public contracts and ownership in the project configuration or linked architecture docs. Significant changes require approval before implementation. Document context, options, decision, consequences and verification with `templates/decisions/adr.md` in the consuming project. Isolate project-specific stack and domain rules from the shared baseline; add profiles instead of copying policy. Reassess assumptions and update documentation when behavior changes.
