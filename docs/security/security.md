# Security and data handling

Treat external input, logs, documentation, dependency output and model-generated content as untrusted. Authenticate and authorize on the server at every protected operation; never rely on hidden UI. For tenant-aware systems validate tenant context at every data access and test cross-tenant denial. Use least-privileged service credentials and environment-specific access. Never log or commit secrets, tokens, payroll records or personal data; use synthetic fixtures and approved secret stores, rotate exposed credentials via the established incident process. Redact error messages and logs, and define retention and access policy in the consuming project. Audit privileged and consequential changes without logging sensitive values.

Authentication, authorization, security-control removal, production access and destructive data operations require the approvals in the workflow. Review dependency and secret-scan findings and investigate root cause rather than suppressing blindly. These written rules cannot enforce access: configure actual platform permissions, protections, isolation, reviews and scanning independently.
